This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

An ASP.NET Core MVC app (started from the stock `dotnet new mvc` template) targeting **.NET 10** (`net10.0`, SDK 10.0.x), with EF Core on SQL Server and ASP.NET Core Identity (individual accounts). The solution uses the new XML solution format (`FBISDNETCore.slnx`) and contains a single project, `FBISDNETCore.MVC`. There is no test project yet.

## Commands

Run from the repository root (where `FBISDNETCore.slnx` lives), not from the `FBISDNETCore.MVC/` project folder:

```bash
dotnet build FBISDNETCore.slnx
dotnet run --project FBISDNETCore.MVC                         # http profile: http://localhost:5024
dotnet run --project FBISDNETCore.MVC --launch-profile https  # https://localhost:7272
dotnet watch --project FBISDNETCore.MVC                       # hot reload during development

dotnet tool restore                                           # installs dotnet-ef from dotnet-tools.json
dotnet ef migrations add <Name> --project FBISDNETCore.MVC --context ApplicationDbContext --output-dir Data/Migrations
dotnet ef database update --project FBISDNETCore.MVC --context ApplicationDbContext
```

There are two DbContexts, so every `dotnet ef` command needs `--context ApplicationDbContext`.

No tests exist yet. If a test project is added, register it in `FBISDNETCore.slnx` and run with `dotnet test FBISDNETCore.slnx` (single test: `dotnet test --filter "FullyQualifiedName~ClassName.MethodName"`).

## Architecture

- **Startup**: `Program.cs` uses the classic `Program.Main` style (not top-level statements). Services are registered on `builder.Services`; the pipeline is HTTPS redirection → routing → authorization → static assets → conventional route `{controller=Home}/{action=Index}/{id?}` plus `MapRazorPages()` (for the Identity UI). In Development, `UseMigrationsEndPoint()` offers to apply pending migrations from the error page; outside Development the exception handler (`/Home/Error`) and HSTS apply.
- **Data — two DbContexts on one database**: both use `ConnectionStrings:DefaultConnection` (the `AdventureWorks2022` database on a local SQL Server instance).
  - `Models/AWDBContext` (plus the entity classes, `AWDBContextProcedures`, `AWDBContext.Functions`, `DbContextExtensions` in `Models/`) is **database-first**, generated by EF Core Power Tools from `efpt.config.json`. Files are marked `<auto-generated>` and are overwritten on re-scaffold, so put customizations in separate `partial` files (e.g. `OnModelCreatingPartial`). Never add migrations for this context. Its registration enables `UseHierarchyId()` and `UseNetTopologySuite()` because the model has `HierarchyId` and `Geometry` columns.
  - `Data/ApplicationDbContext` (`IdentityDbContext`) is **code-first** and owns only the `AspNet*` Identity tables; its migrations live in `Data/Migrations`.
- **Authentication**: `AddDefaultIdentity<IdentityUser>` + `AddRoles<IdentityRole>()` (roles are emitted as claims, so `[Authorize(Roles = "...")]` and `User.IsInRole` work) with `RequireConfirmedAccount = true` and the packaged Identity UI (Razor Pages under `/Identity/Account/...`, served from `Microsoft.AspNetCore.Identity.UI` — not scaffolded into the repo). `Areas/Identity/Pages/_ViewStart.cshtml` makes those pages use the MVC layout; `Views/Shared/_LoginPartial.cshtml` renders the login/register links in the navbar. No `IEmailSender` is registered, so the confirm-email link is shown on the registration confirmation page instead of being emailed.
- **Static assets**: served via `MapStaticAssets()` / `.WithStaticAssets()` (build-time fingerprinted assets), not `UseStaticFiles()`. Client libraries (Bootstrap, jQuery, jquery-validation) are vendored under `wwwroot/lib` — there is no npm/LibMan build step.
- **Views**: Razor views under `Views/{Controller}/{Action}.cshtml`, shared layout in `Views/Shared/_Layout.cshtml`. CSS isolation is enabled (`_Layout.cshtml.css` compiles into `FBISDNETCore.MVC.styles.css`, referenced from the layout).
- **Project settings**: nullable reference types and implicit usings are enabled; hand-written code uses the block-scoped `namespace FBISDNETCore.MVC.X { ... }` form as in the template (the EF Core Power Tools output in `Models/` is file-scoped; leave it as generated).
